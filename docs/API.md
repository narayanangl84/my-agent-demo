# API Documentation

## Overview

The **Documentation Agent** consists of a set of LangChain agents that collaborate to manage project documentation, release notes, issues, and code reviews. The core orchestration is defined in `src/agents/graph.py`.

## Main Components

| Module | Description |
|--------|-------------|
| `src/agents/graph.py` | Defines the LangChain agents, sub‑agents, and tool wrappers. It also creates the central `github_agent` that delegates tasks. |
| `src/agents/utils.py` | Helper functions that adapt LangChain tools (e.g., `rename_tool`, `get_documentation_tools`). |
| `src/workflow/main.py` | Entry point to run the coordinator agent. |
| `docs/API.md` | This generated API reference. |

## Agent Definitions

### Documentation Agent

- **Name**: `documentation_agent`
- **Purpose**: Write and update README files, API docs, and other documentation.
- **Tools**: Uses file‑reading, code‑search, and file‑creation tools provided by LangChain.
- **Prompt**: 
  ```text
  You are a documentation agent. Your task is to help write and maintain project documentation, including README files, API docs, and other relevant materials. Use the provided tools to read existing files, search code, and create or update documentation as needed. Always ensure that the documentation is clear, concise, and up-to-date with the latest project changes. Always include the full result of your work in your final message so the coordinator can see it.
  ```

### Release Notes Agent

- **Name**: `release_notes_agent`
- **Purpose**: Generate release notes from PRs, commits, and issues.
- **Tools**: GitHub API wrapper for releases, changelog extraction.

### Issue Agent

- **Name**: `issue_agent`
- **Purpose**: Search, retrieve, and comment on GitHub issues.

### Code Review Agent

- **Name**: `code_review_agent`
- **Purpose**: Review pull requests and provide feedback.

## Tool Wrappers

Each sub‑agent is exposed as a LangChain `@tool` function, enabling the central coordinator to invoke them via tool calls. The wrappers convert the sub‑agent's response into a `Command` that updates the conversation with a `ToolMessage`.

## Running the Agent

```bash
python -m src.workflow.main
```

The script triggers the `github_agent` with a user prompt. The coordinator decides which sub‑agent to call based on the task description.

## Extending the API

To add new functionality:
1. Implement a new sub‑agent in `src/agents/graph.py` or a new utility in `src/agents/utils.py`.
2. Wrap it with `@tool` and add it to the `github_agent` tool list.
3. Update the documentation in this file accordingly.
